# Trade-off Analysis Table

This table connects each system component to the evaluation criteria used in the thesis.

| Component | Main Benefit | Main Cost / Risk | Evaluation Criteria | Metrics to Report | Thesis Interpretation |
|---|---|---|---|---|---|
| detector_only | Fast, cheap baseline with no LLM dependency. | Higher false-positive risk and limited semantic validation. | Alert Quality, Operational Cost | detector_only: F1=0.2143, FPR=0.1197, LLM calls=0 | Use as the baseline for measuring whether RAG/LLM reduces false alarms. |
| llm_without_rag | Tests whether an LLM can validate alerts from metrics alone. | May suppress false positives but loses true positives without operational context. | Alert Quality, Contextual Effectiveness | llm_without_rag: F1=0, FPR=0.0352, LLM calls=30 | Shows that LLM judging needs retrieved context; metric-only prompts are not reliable in these slices. |
| hybrid_rag | Combines detector candidates with retrieved log/trace context. | Adds retrieval and LLM latency/cost. | Alert Quality, Contextual Effectiveness, Operational Cost | hybrid: F1=0.3, FPR=0.0978, LLM calls=20 | Improves quality over detector-only by giving the judge operational evidence. |
| hybrid_bm25_top6 | Uses local hybrid BM25/hash retrieval with top_k=6. | Slight retrieval latency cost; context coverage remains limited. | Contextual Effectiveness, Operational Cost | hybrid_bm25_top6: F1=0.3429, FPR=0.0458, LLM calls=30 | Best practical local RAG baseline in Phase 4; improves F1/FPR over detector-only. |
| hybrid_bm25_top10 | Retrieves more context per candidate. | More context tokens without classification improvement in this slice. | Contextual Effectiveness, Operational Cost | hybrid_bm25_top10: F1=0.3429, FPR=0.0458, LLM calls=30 | Increasing top-k from 6 to 10 raises average context but does not improve F1 here. |
| context_rescue | Promotes candidates using log/trace signals that metric-only detection may miss. | Increases candidate alerts and LLM calls. | Alert Quality, Operational Cost, Operational Risk | context_rescue: F1=0.7805, FPR=0.0317, LLM calls=55 | Improves recall and F1 substantially, trading higher inference cost for lower false-negative risk. |
| local_first | Uses local Ollama first and API fallback for uncertain/error cases. | Higher local latency; still needs API fallback for quality. | Operational Cost, Operational Risk, Alert Quality | local_first_ollama_gemini: F1=0.7692, FPR=0.1714, LLM calls=6 | Feasible workflow for reducing API dependence, but not yet a full replacement for external LLMs. |
| scheduler_cache | Controls external calls with cache, retry/cooldown, and budget-aware handling. | May defer or manual-review alerts when budget is exhausted. | Operational Cost, Operational Risk | gemini25_flash_lite_500w_budget_manual_review_cache_replay: F1=0.4631, FPR=0.14, LLM calls=120 | Makes quota/cost visible and prevents unconfirmed budget-exhausted candidates from being routed as true alerts. |
| streaming_replay | Processes windows sequentially and prevents future context leakage. | Smoke setting is not directly comparable with batch benchmarks. | Real-time Feasibility, Operational Risk | streaming_hybrid: F1=0.4167, FPR=0.1143, LLM calls=9 | Supports real-time feasibility claims, but not production readiness. |
